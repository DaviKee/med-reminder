### 3.1 三条最重要的结论

**① ⭐⭐ 代理提醒（reminderAgentManager）是鸿蒙给我们的真礼物 —— 应升格为移植核心议题**

它不是 Capacitor 插件的附属品，而是**系统级定时提醒服务**：应用被杀、退出后照样触发。
能力远超我们的需求 —— 原生支持**稍后提醒**（`snoozeTimes`+`timeInterval`）、**排除日期**（`addExcludeDate`，即"跳过某天"）、**原地更新**（`updateReminder`）、**取消正在显示的提醒**（`cancelReminderOnDisplay`）。
API 26 还新增了 `repeatInterval`+`repeatCount`，官方举的应用场景**原文就是「用药应用按周期提醒，疗程结束自动停止」**。

> ⚠️ **但有一条生死线，09-29 晚已实测确证**：
> - **`publishReminder` 报 `1700002`** —— 声明权限 + 权限已授予（`grantStatus=0`）**都没用**，
>   我们**在模拟器上**就被拦住了。
> - **必须去 AGC 申请**：`项目设置 → 开放能力管理 → 代理提醒 → 申请`（填原因 + 上传场景截图和分类截图）
>   → 审批约 **8 个工作日** → 通过后**「必须重新生成 Profile 文件并使用手动签名」**，否则仍报 1700002。
> - ✅ **准入类型含「医疗类 / 运动健康类 / 生活服务类」—— 我们在范围内**，且是正当健康场景。
> - ✅ **附带好消息**：`getPending` 的"Permission denied"**只是没声明权限**，声明后三个查询 API 全部可用
>   → **通知清场机制不用改设计**（我原来的判断是错的，已修正）。

**② 两个「否」，省下大量时间**

| | 结论 | 依据 |
|---|---|---|
| **实况窗（Live View Kit）** | 🚫 **我们用不了，直接从排期划掉** | 官方场景准入**明确排除"待办/单点提醒"**；16 类场景无「服药提醒」；最接近的 TIMER 也"仅限工具类"；**申请门槛是"月活 ≥1000 且已上架"**，我们达不到 |
| **热更新** | 🚫 **红线** | 审核驳回码 908166；禁止 `eval`/`new Function`/动态加载远程代码。⚠️ `hionic` 装插件时引入了 **`HotCodePushPlugin`**，**必须确认没被打进 HAP** |

**③ 三条排期的重新评估**
