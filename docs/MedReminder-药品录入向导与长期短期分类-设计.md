# MedReminder-药品录入向导与长期短期分类-设计

> 调研日期：2026-10-10 ｜ 状态：**设计稿，待秦老师拍板后实施**
> 需求来源：秦老师反馈 —— ①「添加药品选项做成每次选择一项，不要长列表」②「长期服药与短期服药分开，短期要有退出方案」
> 调研方式：联网检索 Medisafe 官方手册 / 少数派 9 款服药 App 横评 / NHS 临床系统 / Android 药历类开发实践

---

## 0. 一句话结论

**向导式录入**：把现有"一屏全填"的表单改成 **4 步向导，每屏一个问题、大按钮单选**（Medisafe 同款结构）。
**长期/短期分类**：**数据层零新增字段** —— 现有 S-4 疗程就是"短期退出方案"（起止日期 + 到期自动停用），
缺的只是**展示层分组**：药品页分成「长期服药 / 短期用药」两组。**排程与打卡逻辑完全不动**。

---

## 1. 竞品调研结论（证据）

### 1.1 Medisafe 的向导式录入（行业标杆，1000 万+ 用户）

官方手册逐屏拆解，流程是**每屏一个问题**：

```
药名（搜索/手填）→ 剂型（药片/液体胶囊…，选品牌药会带推荐）→ 服用方式+剂量（"口服-丸-200mg"）
→ 频率（每天/每周某几天/每隔X天/周期(21+7)/按需）→ 各次剂量的时刻与数量 → 可选项（治疗时长/库存/说明/外观）→ 预览保存
```

关键设计：
- **剂量单位跟剂型挂钩**（选"药片"单位才是"片"，选"液体"单位是 ml）—— 不让用户面对无关选项；
- 频率每个选项一句话解释；最后**预览页用大白话复述**；
- 治疗时长有"**持续治疗**"（无结束日期）选项 —— 正是"长期"。

### 1.2 长期/短期两分法 —— 临床界早有标准做法

NHS 系 EHR（Jump）：用药分 **Acute（急性/短期，一个疗程）** 与 **Repeat（长期重复）**，
另有 Paused / Past。Medisafe 的"治疗时长"= 开始日期 + 结束日期，**结束日期未知就选"持续治疗"**。
→ 秦老师的"长期循环不动 / 短期临时加 + 退出方案"与临床 Acute/Repeat 语义完全同构，
**不是新发明，是有行业共识的两分法**。

### 1.3 老人向的经验清单（koder.ai 实践 + 少数派横评）

- 分步表单：第一步名称剂量 → 第二步时间 → 第三步重复规则；时间用滚轮/选择器，**杜绝手输文本**；
- **常用预设一键选**："每天一次""每天两次""每 8 小时" 作为大按钮，默认时刻（早 8:00 等）可改；
- 常见药**模板预填**（如"氨氯地平 5mg 每日一次"）；
- 每个选项带一句话解释，专业词（如"国际单位"）不如包装上的写法；
- 任何建议都标"Suggested"，不做医疗决定。

## 2. 与现有能力的映射（重要：大半已经做好了）

| 向导需要 | 现有能力 | 差距 |
|---|---|---|
| 单次剂量 / 单位 / 服用说明 | **S-1**（v1.4.14，三个可空字段） | 只有文字输入，缺**剂型→单位**的预设联动 |
| 用药频率 | interval（每隔 X 小时）/ fixed（固定时刻）/ weekly（每周几，S-3） | **三种模式齐了**，缺**快捷预设**（一日一次/两次/三次） |
| 短期退出方案 | **S-4 疗程**（起止日期 + 到期自动停用 + 结束提醒） | **已经有**，只差把它包装成"短期用药" |
| 长期循环 | med 无结束日期即一直循环（默认现状） | 无 |
| 库存 | S-2（剩余量/低库存/预计用完日） | 无 |

→ **本次新增的真实工作量**：① 表单改向导（交互重构，不改数据结构）② 剂型/单位预设清单 ③ 频率快捷预设 ④ 药品页分组显示。**不改数据模型、不改排程引擎、不改打卡**——旧数据天然兼容。

## 3. 方案 A：录入向导（4 步）

### 第 1 步 · 这个药是什么
- 药名：文本输入（保持现状，不搞药品数据库——本地优先、无联网的产品定位不变）；
- **剂型**（单选 chips，决定第 2 步的单位）：
  `片剂` `胶囊` `颗粒` `口服液` `丸剂` `含片` `缓释片` `泡腾片` `贴剂` `喷剂` `滴剂` `软膏` `其他`
  （覆盖国内常见口服剂型；"其他"自由输入，不强凑分类）

### 第 2 步 · 怎么吃
- 单次剂量：数字输入 + **单位下拉**（跟剂型联动）：

  | 剂型 | 单位选项 |
  |---|---|
  | 片剂/缓释片/泡腾片/含片 | 片 |
  | 胶囊 | 粒 |
  | 颗粒 | 袋 |
  | 口服液 | 支 / 毫升 |
  | 滴剂 | 滴 |
  | 丸剂 | 丸 |
  | 贴剂 | 贴 |
  | 喷剂 | 喷 |
  | 软膏 | 次 |
- 服用说明（单选 chips，可跳过）：`餐前` `随餐` `餐后` `睡前` `空腹` `不限`

### 第 3 步 · 什么时候吃
- **模式三选一**（大按钮，现有三种排程模式换个入口）：
  - `固定时刻`（最常用，放第一个）→ 快捷预设：**一日一次**（早餐后 8:00）/ **一日两次**（早 8:00 晚 20:00）/ **一日三次**（三餐 8:00/12:00/18:00）—— 选中即预填时刻，可改；
  - `每隔几小时`（interval）；
  - `每周指定几天`（weekly）。

### 第 4 步 · 吃多久（长期 / 短期的选择点）
- **两个大按钮**：
  - `长期服用` —— 一直循环，不设结束日期（默认选中：多数慢病药属于此类）；
  - `短期疗程` —— 设开始/结束日期，**到期自动停药并提醒**（=S-4 现有能力）。
- 短期再给快捷选项：`7 天` / `14 天` / `自选日期`。

### 确认页
大白话复述 + 保存：**"氨氯地平，每天 1 片，早餐后吃，长期服用。"**
确认页是向导的"防错锚点"—— 老人不需要回头检查表单，读一句话就够。

### 老人向原则（贯穿）
- 每屏一个问题；选项是大 chips 不是长列表；有合理默认；非必填可跳过；
- 编辑现有药品 = 同一向导，预填当前值；
- 不引药品数据库（本地优先、无账号无联网，产品定位不动摇）。

## 4. 方案 B：长期 / 短期分组展示

### 4.1 分类规则（派生，不加字段）
```
med.end 为空            → 长期服药（一直循环）
med.end 有值且未到期     → 短期用药（疗程中，显示"还剩 N 天"）
med.end 已到期（已停用） → 归入"已结束"（现有 courseState 逻辑）
```
新增一个纯函数 `medClass(m)`（core/schedule.js），药品页与确认页共用 —— 口径只有一份。

### 4.2 药品页分组
- 药品列表分两段：**「长期服药」**（默认在上，一般不动）与 **「短期用药」**（临时加的，卡上带"还剩 N 天 / 到期自动停"角标）；
- 短期卡的**退出方案**（三层，都是现有能力换文案）：
  ① 到期自动停（S-4 已有，到期日提醒一次）；
  ② 病好了提前停：卡上「提前结束」→ 二次确认 → 停排程撤通知（删药有确认+撤通知的既有纪律复用）；
  ③ 医生改了疗程：编辑向导第 4 步改结束日期。
- 分组**只影响展示与录入引导，不影响排程/打卡/历史**——删掉分组功能 App 也照常工作（可回退）。

### 4.3 为什么不做成"两种药品类型"
考虑过给 med 加 `kind: 'long'|'short'` 字段，**否决**：
- 与 med.end 派生信息重复，两处状态会打架（改了 end 忘改 kind）；
- 旧数据没有 kind，要做迁移；
- 临床语义上"长期/短期"本来就由疗程长短决定，不是药品固有属性 —— 高血压药吃十年是长期，抗生素吃七天是短期，**同一种药两者都可能是**。

## 5. 实施估算与顺序

| 项 | 内容 | 量级 |
|---|---|---|
| M1 向导 | sheet.js 表单 → 4 步状态机（复用现有保存逻辑与全部校验） | 中（最大头） |
| M2 词汇表 | 剂型/单位/频率预设常量 + spec | 小 |
| M3 分组 | medClass() + 药品页分组渲染 + 短期卡角标/「提前结束」 | 中 |
| M4 spec | 现有 meds/meds-save/med-fields/course 全量回归 + 新增 | 小 |

**建议一次会话做完 M1+M2，单独一次做 M3+M4** —— 向导是纯交互重构（行为等价性由 spec 兜底），分组涉及展示逻辑，分开出包便于定位回归。

---

## 6. 风险与不做的事

- ❌ 不加药品数据库 / 不联网查药（本地优先铁律）；
- ❌ 不改排程引擎与打卡流程（向导只是录入 UX）；
- ❌ 不做 `kind` 字段（§4.3）；
- ⚠️ 向导重构触及 `ui/sheet.js`（保存防重入、编辑态）—— 该模块的 spec（meds-save 14 条等）必须全量回归；
- ⚠️ 旧药品没有剂型信息 → 编辑时剂型显示"其他/未设"，不强制补填。
